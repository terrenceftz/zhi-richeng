# 主题系统 · 修改记忆（以星之卡比为参考实现）

> 用途：记录「星之卡比」主题在本项目中的**所有改动点**与实现模式，作为后续用新素材制作其它主题的模板。
> 阅读对象：任何要新增/修改特色主题的人（含 AI 助手）。**原则：主题只影响展示层，绝不触碰数据与业务逻辑。**

---

## 一、主题架构（3 层）

```
palette 键值（themeStore） → data-palette 属性（<html>） → CSS 变量（--brand-*）→ Tailwind brand-* 类
```

| 层 | 文件 | 作用 |
|---|---|---|
| 色板注册 | `client/src/stores/themeStore.ts` | `Palette` 类型、`PALETTES` 列表（名称/描述/色卡/special 标记）、`applyTheme()` 写 `data-palette` + 切换 favicon |
| 颜色变量 | `client/src/index.css` | `[data-palette='<key>'] { --brand-50 … --brand-950 }`（RGB 三元组，如 `236 72 153`），Tailwind `brand-*` 经 `tailwind.config.js` 映射到这些变量 |
| 素材目录 | `client/public/themes/<key>/` | 图片素材（banner/login/calendar/icon/stickers），经 `public/` 根路径引用 |

## 三、核心装饰组件（`client/src/components/theme/KirbyDecorations.tsx`）

所有装饰组件**内部**做 `useThemeStore((s) => s.palette === 'kirby')` 判断，非当前主题返回 `null` → **主题隔离**（默认主题不受影响，无需逐处 else）。

| 组件 | 用法 |
|---|---|
| `KIRBY_STICKERS` | 贴纸名 → 路径映射表（新增素材在这里登记） |
| `KirbyPageDecorations` | 全站页面背景装饰（AppLayout 挂载一次，`absolute inset-0` + 低透明度贴纸） |
| `KirbyHeroDecorations` | 首页问候卡内装饰 |
| `KirbyCornerSticker` | 卡片角贴纸。⚠️ **不内置定位类**（absolute/right/top 由调用方 className 传入），否则 Tailwind 同属性覆盖冲突 |
| `KirbyMiniCalendarDecorations` / `KirbyCalendarPanelDecorations` | 小日历 / 日历面板装饰 |
| `KirbyHeaderSticker` | 标题右侧小贴纸（inline 流内） |
| `KirbyTitleIcon` | 页标题图标：kirby 主题下用贴纸**替换** lucide 图标（避免重复），其它主题返回原图标 |

## 五、首页 Banner 机制（本次新增，每个主题独立）

`pages/DashboardPage.tsx`：

```tsx
// 主题专属首页 banner：仅登记了素材的主题用本地图，其余回退必应每日壁纸
const THEME_BANNERS: Partial<Record<Palette, string>> = {
  kirby: '/themes/kirby/banner.jpg',
};
const themeBanner = THEME_BANNERS[palette];
```

- 有 `themeBanner` → 用本地图、**跳过必应壁纸请求**、隐藏版权角标；
- 无 → 回退必应每日壁纸（原逻辑），再兜底品牌渐变。
- **新增主题 banner 只需两步**：素材放 `public/themes/<key>/banner.jpg` + 表里登记一行。

## 六、新增一个主题的完整步骤（Recipe）

假设新主题 key = `<key>`，名称「XXX」：

1. **准备素材**：
   - 10 档品牌色 RGB 三元组（`--brand-50 ~ --brand-950`）；
   - 图片：`banner.jpg`（首页）、`login.jpg`（登录页）、`icon.png`（logo/favicon）、`calendar.jpg`（日历页）、透明贴纸 `stickers/*.png`（可选）。
2. **注册色板**：`index.css` 追加 `[data-palette='<key>'] { --brand-* }`；`themeStore.ts` 的 `PALETTES` 加一项（带素材则 `special: true`）。
3. **放素材**：`client/public/themes/<key>/`（可整个复制 kirby 目录改图）。
4. **建装饰组件**：新建 `components/theme/<Key>Decorations.tsx`，复制 Kirby 的结构，替换 `KIRBY_STICKERS` 映射 + 把所有 `palette === 'kirby'` 判断改为 `palette === '<key>'`。
5. **登记 banner**：`DashboardPage.THEME_BANNERS` 加一行 `<key>: '/themes/<key>/banner.jpg'`。
6. **替换引用点**：按第四节清单逐处把 `palette === 'kirby'` 改为新 key（或改造为通用判断）。
7. 若新主题**不打算要装饰**（纯色板主题），则只需第 1、2 步（同 ocean/forest 等纯色主题的做法）。

## 七、约定与注意事项（踩坑记录）

1. **主题隔离**：装饰组件内部 gating，`palette === 'xxx'` 不命中即返回 `null`，默认主题永不出现卡比元素。
2. **禁止硬编码粉色**：主题卡只用 `brand-*`（变量驱动）+ `slate-*` + `dark:`，kirby 专属色一律走 CSS 变量。
3. **KirbyCornerSticker 不内置定位类**：定位全由调用方传，避免 Tailwind 同属性覆盖（已踩坑，勿改回）。
4. **素材必须透明 PNG**：贴纸是透明 PNG，转换时勿加背景；裁切必须完整（此前素材裁切不完整已重切替换过一次）。
5. **装饰组件的容器**：一律 `pointer-events-none absolute inset-0 overflow-hidden`，避免遮挡点击。
6. **泛化方向（尚未做）**：目前所有 gating 硬编码 `palette === 'kirby'`。若未来要**同时支持多个特色主题并存**，建议把 gating 泛化为 `isSpecial(palette)` 或按主题注册装饰配置（如 `{ kirby: { banner, decorations } }`），避免逐处 if 扩散。
7. **主题与数据解耦**：palette 仅存 localStorage（`localStorage.palette`），不写入后端；切主题不影响任何数据。
