# 数据迁移操作说明（一键导出 / 导入）

> 适用场景：把本系统**整站数据**从一台服务器迁移到另一台（如部署到 VPS），或在换机时完整搬迁。
> 迁移内容包括：**系统设置、用户账号（含密码）、学生花名册、心理台账档案与跟进记录、谈心谈话、日程任务、通知、灵感、周期提醒**。

---

## 一、功能入口

| 操作 | 入口 | 权限 |
|------|------|------|
| 导出迁移包 | 设置 → 系统管理 → **一键迁移**（导出）｜ 导出中心 → **全量数据迁移包** | 仅管理员 |
| 导入迁移包 | 设置 → 系统管理 → **一键迁移**（导入） | 仅管理员 |

迁移包为单个 `.json` 文件（格式版本 `v1`，含 `app`/`formatVersion` 标识），文件名形如 `数据迁移备份-20260809-0844.json`。

---

## 二、导出（在旧服务器上）

1. 以管理员登录，进入「设置 → 系统管理 → 一键迁移」。
2. 点击 **一键导出**，浏览器下载 `数据迁移备份-YYYYMMDD-HHmm.json`。
3. 妥善保管该文件：
   - ⚠️ 文件**包含敏感凭据**（飞书 AppID/Secret、DeepSeek API Key、IM Token、飞书 OpenID 绑定），请勿外传，勿放入公开仓库。
   - 建议同时通过「设置 → 数据备份」下载一份 `.db` 二进制备份双保险（.db 文件同样含全部数据与凭据）。

> 迁移包**不包含**：刷新令牌（会话一次性）、审计日志（运维记录）、提醒去重标记（可自动重建）。导入后需用原账号密码重新登录。

---

## 三、部署新服务器（VPS）

单容器部署时后端会自动建表并托管前端构建产物，无需手工操作：

```bash
git clone <仓库> && cd <仓库>
# 1. 配置环境变量（生产环境必填，缺失会拒绝启动）
cp server/.env.example server/.env   # 若存在示例文件；否则参照下方最小配置
```

最小 `.env`（`server/` 目录）：

```dotenv
DATABASE_URL="file:./dev.db"
JWT_ACCESS_SECRET="<强随机字符串>"
JWT_REFRESH_SECRET="<另一组强随机字符串>"
CLIENT_URL="https://你的域名"
PORT=3001
```

```bash
# 2. 构建并启动（Dockerfile 内已含 npx prisma db push 自动建表）
docker compose up -d --build
# 3. 验证
curl https://你的域名/api/health   # → {"status":"ok"}
```

## 四、导入（在新服务器上）

1. 用种子管理员账号登录（seed 账号见 `server/prisma/seed.ts`）。
2. 进入「设置 → 系统管理 → 一键迁移」→ 点击 **选择迁移文件**，上传步骤二下载的 `.json`。
3. 确认弹窗勾选继续。系统会：
   - 先自动在服务器 `server/backups/` 写一份当前状态的 `pre-import-*.json` 快照（安全网）；
   - 在**单个事务**内整体替换数据（先清空再按原 ID 重建，失败自动回滚，不留半截状态）；
   - 返回导入计数（账号/学生/台账/谈心/日程…）。
4. 若当前登录账号不在迁移包中，请用**迁移前的账号密码**重新登录。
5. 抽验：学生列表、台账、谈心、日历数据是否齐全；飞书提醒是否正常推送。

> 导入是「整体覆盖」语义：目标库原有数据会被清空替换。请确认目标库为全新部署，或已下载旧数据备份。

---

## 五、故障恢复（误导入 / 导入后发现问题）

每次导入前系统都会把**当前状态**快照到 `server/backups/pre-import-<时间戳>.json`。恢复步骤：

```bash
cd server
npx tsx scripts/restore-from-snapshot.ts                # 恢复最近一份快照
npx tsx scripts/restore-from-snapshot.ts pre-import-20260809-084432.json   # 或指定某一份
```

脚本会列出可用的快照文件，恢复同样在事务内整体替换并**再写一份新快照**保护当前状态。

也可以直接用「设置 → 数据备份」的 `.db` 备份文件恢复到备份时点。

---

## 六、与两种备份方式的区别

| 方式 | 内容 | 用途 | 跨版本兼容 |
|------|------|------|-----------|
| **一键迁移（.json）** | 业务数据 + 设置 + 账号，结构清晰、可读 | 换机 / VPS 部署迁移，可选择性恢复 | 按 `formatVersion` 版本化，后续结构变更可平滑升级 |
| **数据备份（.db）** | SQLite 整个数据库二进制 | 同一版本下的完整冷备/灾难恢复 | 强依赖数据库结构完全一致 |

日常定时冷备仍建议保留 `.db`（`backup-schedule.sh` 已支持自动备份）；**换机/上 VPS 用一键迁移**最稳妥。
